# Coordinated server restart

The sidebar's **Request server restart** holds new runs and mutations across all projects. Current CLI turns finish naturally; the dashboard does not interrupt tools or inject messages into a CLI whose stdin has closed. Once those turns and any existing workspace/delivery operations settle, each affected task receives an explicit restart notification and a read-only handoff request. Preparation runs one handoff at a time, respecting task usage allowances. Local worktree checkpoints and valid handoffs are required before **Restart server** becomes enabled. Expand the agent count for progress and errors; retry failed preparation or cancel to resolve a blocker.

Confirmation rechecks each affected worktree against its saved checkpoint. A failed save, invalid handoff, or external edit blocks restart. This flow does not require a GitHub push. Session IDs, transcripts, handoffs, and isolated worktrees persist, so the owner can continue a task with a new message after restart. Queued role work resumes through the normal scheduler. Completed turns are not automatically repeated.

`server/src/restart.ts` owns the durable barrier in the data directory's atomically replaced `restart.json`. An unexpected shutdown during preparation preserves the hold on the next launch. Only confirmed restarts clear it on startup. `runner.ts` gates scheduling and automation while preparing; HTTP mutations are held too. The sidebar polls status and disables confirmation when disconnected. Preparation deliberately waits indefinitely for a long-running turn; cancel preparation to regain normal Stop controls.

`scripts/server.mjs` supervises the API process for `pnpm start`, `pnpm --filter @ad/server start`, and `pnpm dev`. Confirmed restart closes connections and exits with code 75; the launcher starts a fresh process, reloading server code. Other exit codes do not trigger a restart loop. Directly running `server/src/index.ts` without the supervisor disables the restart request. Development file watching retains its existing automatic restart behavior; it is separate from this owner-confirmed safe restart flow.

Verification: `server/test/restart.test.ts` covers both providers, checkpoint errors, external edits, session recovery, durable queue holds, cancellation, and duplicate/early confirmation. `e2e/restart.spec.ts` exercises the actual launcher restart and browser reconnection.
